# กรอบผู้บริหาร: การ map เมนูเดิม และสิ่งที่เปลี่ยนจากระบบเดิม

ระบบเดิม = 8 หน้าเรียงแบน (Executive Snapshot · กำไรรายสถานี · เงินทุนหมุนเวียน · ธุรกิจและสินค้า · บริษัทและสถานี · ลูกค้าค้าส่ง · Operation · ประเด็นติดตาม)
รุ่นนี้ = เมนูสองชั้นตามกรอบ CEO **โดยหน้าเดิมอยู่ครบทุกหน้า ไม่มีรายงานใดถูกตัดทิ้ง**

## 2. สิ่งที่เพิ่ม

**หน้ากลยุทธ์ (ใหม่)** — ใช้ตัวกรองชุดเดียวกับหน้าขายทุกหน้า
- KPI: ยอดขายรวม · การเติบโตสาขาเดิม (same-store) · สัดส่วน Non-Oil · สัดส่วนค้าส่ง · ปริมาณ LPG เทียบเท่าลิตร
- ตารางเติบโตตามบริษัท / กลุ่มธุรกิจ / ช่องทาง พร้อมส่งออก CSV ทุกตาราง
- สาขาเดิม (มียอดทั้งสองช่วง) · มียอดเฉพาะช่วงที่เลือก · ไม่มียอดในช่วงที่เลือก — นับเป็น "หน่วยธุรกิจ" ไม่ใช่ "สาขา" เพราะหนึ่งสถานีมีได้หลายธุรกิจ
- สินค้าที่ยอดเพิ่ม/ลดมากที่สุด
- ตาราง "สิ่งที่หน้านี้ยังไม่แสดง และเหตุผล"

**หน้าซ่อมบำรุง (ใหม่)** — นำเข้าไฟล์ส่งออกจากระบบ Factorium (ใช้ร่วมกับ SAM และ PSG)
- KPI: ใบงานค้าง · ค้างเกิน SLA · งานด้านความปลอดภัยที่ยังค้าง · แจ้งใหม่ในช่วง · ปิดงานในช่วงพร้อมเวลาเฉลี่ยแจ้ง→ปิด
- ตารางรายสาขา (แจ้ง/ปิด/ค้าง/เกิน SLA/ค้างนานสุด) · แยกตามประเภทงาน ประเภทเครื่องจักร และผู้รับผิดชอบ · ใบงานค้างนานที่สุด · ส่งออก CSV สองชุด
- SLA อ่านจากข้อความ "ระดับความด่วน" ที่ระบบบันทึกจริง (เช่น "ด่วน SLA 3 วัน") — ใบงานที่ไม่ระบุ SLA ไม่ถูกนับว่าเกินกำหนด
- map แผนก → บริษัท/สถานี ด้วย `config/maint_departments.csv` · ใบงานของบริษัทนอกกลุ่ม (HEA) ถูกแยกออกและรายงานจำนวนไว้

**หน้าโครงการ (ใหม่)** — ไม่มีทะเบียนโครงการในแหล่งที่เข้าถึงได้ จึงแสดงสถานะตรง ๆ พร้อมรายการข้อมูลที่ต้องได้ และลิงก์ไปสิ่งที่ใช้ดูแทนได้ระหว่างนี้

**หน้าสถานะข้อมูล (เพิ่มส่วน)**
- Coverage matrix รายบริษัท–สาขา–ธุรกิจ: แหล่งที่คาด (API POS / คีย์มือ) · เอกสารล่าสุด · จำนวนวันที่มีเอกสารใน 30 วันล่าสุด · สถานะ (เป็นปัจจุบัน / ช้า N วัน / ค้าง N วัน / ไม่พบรายการ) — คำนวณจากข้อมูลจริง ไม่ hardcode วันที่
- กฎแปลงหน่วย LPG และฐาน VAT พร้อมวันที่มีผลและผู้ยืนยัน (ดู `docs/LPG-VAT-RULES.md`)
- ตารางความพร้อม KPI 20 ตัวตามกรอบ CEO (ดู `docs/KPI-READINESS.md`)

**ชั้นข้อมูล**
- `config/lpg_factor.csv` + `scripts/build_lpg.py` → `data/lpg.json` (ค่าแปลงหน่วย LPG แบบมีประวัติ)
- `star.js` เพิ่ม `lpgRow / kgToLitre / lpgLitreEq` — เลือก factor ตามวันที่ของเอกสาร และคืน `null` เมื่อไม่มีค่าที่ยืนยัน (ไม่เดา)

## 3. สิ่งที่ตั้งใจไม่ทำ (ตามโจทย์)

| ไม่ทำ | เหตุผล |
|---|---|
| Pipeline / Win Rate / Sales Cycle | ไม่พบเอกสาร lead ใน connection ที่ตรวจ และ SO อย่างเดียวไม่ใช่ pipeline |
| CLV | ยังไม่มีนิยามอายุลูกค้าและต้นทุนต่อลูกค้า · ยอดซื้อสะสมไม่ใช่ CLV |
| Market Segment | ยังไม่มีทะเบียนกลุ่มลูกค้า/พื้นที่ที่ยืนยัน — ไม่สร้าง segment เองจากชื่อลูกค้า |
| Resource Utilization | ไม่มีชั่วโมงจัดสรร/ทำงานจริง — ไม่ใช้จำนวนใบงานหรือระยะเวลาเปิด–ปิดแทน |
| คะแนนความเสี่ยงรวม | ซ้ำกับฝ่ายความเสี่ยง — ใช้สถานะเทียบเป้าและความครบถ้วนข้อมูลแทน |
| LPG Planning / TankConfig / Demand Forecast / จุดสั่งซื้อ / แผนเติมถัง | อยู่ใน Power BI เดิมแล้ว และโจทย์ระบุไม่ให้ทำซ้ำ |
| รวมลิตร + กิโลกรัม เป็นปริมาณเดียว | หน่วยต่างชนิดกัน — แปลงเฉพาะช่องที่เขียนกำกับว่า "เทียบเท่าลิตร" |
| เรียกยอดรวมสามบริษัทว่างบการเงินรวม | ยังไม่ตัดรายการระหว่างกัน — ใช้คำว่า "ยอดรวมสามบริษัทก่อนตัดรายการระหว่างกัน" |
