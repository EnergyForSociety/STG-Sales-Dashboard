# หน้าโครงการและการส่งมอบ (Project.dc.html)

หน้านี้ตอบ 4 คำถามของ CEO: **แต่ละบริษัทกำลังส่งมอบอะไร · งานไหนเกินกำหนด · ขั้นถัดไปคืออะไร · มีเอกสารเงินที่ยืนยันแล้วเท่าไร**
สถานะและแผนงานมาจาก ClickUp ส่วนเงินมาจาก TRCloud ของแต่ละบริษัท ทั้งสองระบบใช้แบบอ่านอย่างเดียว

## แหล่งข้อมูลและสิ่งที่พบ (ดึง 21 พ.ย. 2569)

ข้อค้นพบสำคัญ:
- ช่อง **project** ในเอกสาร PO/AP ของทั้งสามบริษัทว่างทุกฉบับที่ตรวจ เชื่อมโครงการได้เฉพาะผ่าน `warehouse` (= รหัสแผนกสถานี) และข้อความในเอกสาร จึงจัดเป็น "คู่ที่เสนอ" ทั้งหมดจนกว่าบัญชีจะยืนยัน
- AP อ้างเลข PO (ช่อง `po`) ได้ จึงใช้ AP เป็นยอดบันทึกบัญชีและคำนวณภาระคงเหลือ = PO − AP โดยไม่บวกซ้ำ
- ClickUp มีช่อง Budget แต่ไม่มีงานใดกรอก · ช่อง Expense มีค่า 0 เฉพาะ List ที่ตัดออก · ไม่มีชั่วโมงทำงาน (time spent) → Resource Utilization แสดง "ข้อมูลไม่พอ"

## วิธีแยก STG / STP / TWP

ไม่มี custom field บริษัทหรือสาขาใน ClickUp จึงใช้หลักฐานตามลำดับนี้ และบันทึกไว้ในคอลัมน์ `evidence` ของทะเบียนทุกแถว
1. ชื่อสถานีในชื่องาน/ข้อความ เทียบกับ `config/stations.csv` (เช่น ซันไชน์ = STG-05, ธวัชภิญโญ ขาเข้า = TWP-IN)
2. ธุรกิจของ List: LPG ค้าปลีก/ค้าส่ง = STG, NGV = TWP, น้ำมัน PT = STP, น้ำมัน PTT มีทั้งสามบริษัท → **รอยืนยันบริษัท**
3. เอกสาร TRCloud ที่ `warehouse` ตรงสาขา

ทะเบียนแยก 3 ฟิลด์: บริษัทเจ้าของ (`owner_company` = STG/STP/TWP/`JOINT:STG+TWP`/`PENDING`) · สาขาที่ดำเนินงาน (`station_ids`) · บริษัทที่ลงบัญชี (มาจากเอกสารใน `project_finance_map.csv`)

## ความหมายของตัวเลขบนหน้า

- **โครงการยืนยันแล้ว** นับเฉพาะ `kind = โครงการ` ที่ `status = confirmed` และมีผู้ยืนยัน · รายการที่ยังเป็น `proposed` แสดงในตารางพร้อมป้าย "รอยืนยัน" และนับในการ์ด "รายการรอยืนยัน"
- หน่วย: **โครงการ** = รายการประเภทโครงการ · **งาน** = งาน ClickUp · **รายการ** = ทุกประเภทในทะเบียน (โครงการ โอกาสธุรกิจ/สัญญา งานศึกษา งานกฎหมาย แผนงานธุรกิจ งานบริหารองค์กร)
- **สถานะโครงการ** ดูจากงานหลัก: ปิดครบ = เสร็จ (ถ้างานย่อยยังเปิดจะขึ้น "เสร็จ · งานย่อยค้าง") · ยกเลิกทั้งหมด = ยกเลิก (แยกจากเสร็จ) · พักไว้/ยังไม่เริ่ม ตามสถานะงานหลัก
- **งานเกินกำหนด** = ยังไม่เสร็จและไม่ยกเลิก และกำหนดส่ง < วันอ้างอิง (วันที่ดึง ClickUp ตามเวลา Asia/Bangkok) · นับทุกระดับงานย่อย
- **สัดส่วนงานย่อยที่เสร็จ** = งานย่อยเสร็จ / งานย่อยทั้งหมด (ไม่นับงานยกเลิก) แยกจาก **ความคืบหน้าหน้างาน** ซึ่งต้องให้เจ้าของโครงการกรอกในทะเบียน
- **เงิน** 4 ฐานแยกกัน: งบอนุมัติ (ยังไม่มีในระบบ) · มูลค่า PO ก่อน VAT = ภาระผูกพัน · AP ก่อน VAT ที่อ้าง PO = ยอดบันทึกบัญชี · จ่ายแล้ว (รวม VAT ตาม AP) · รวมเข้ายอดโครงการเฉพาะคู่ `confirmed` · ยอดกลุ่มเป็นผลรวมตามเอกสาร ยังไม่ตัดรายการระหว่างบริษัท · ประเภทต้นทุน (สินทรัพย์/งานระหว่างก่อสร้าง/ค่าใช้จ่าย) รอบัญชีระบุ

## วิธีอัปเดต Snapshot

1. **ClickUp** (Claude Code/Codex ที่มี ClickUp MCP): `clickup_get_workspace_hierarchy` ตรวจว่ายังมีแค่ Space STG หรือมี Space/List ใหม่ → `clickup_filter_tasks(space_ids=[901811856472], include_closed=true, subtasks=true)` อ่านทุกหน้าจน `has_more=false` → `clickup_execute_operator(task.get_many)` ขอ `direct_parent, time_mgmt, text_content, fields` ของทุก Task ID → บันทึกเป็น `raw/clickup_STG_<YYYY-MM-DD>.json` ตามโครงสร้างไฟล์เดิม (`fetched_at`, `lists`, `tasks[]`)
2. **TRCloud** (MCP STG-TRCLOUD / STP-TRCLOUD / TWP-TRCLOUD, user อ่านอย่างเดียว): `search_po`, `search_ap`, `search_exp` ของผู้รับเหมาและคำค้นงานปรับปรุง/สาขาในทะเบียน แยกบริษัท → `raw/trcloud_project_docs_<YYYY-MM-DD>.json` (ใส่ `status` ของแต่ละบริษัท; ถ้าโหลดไม่สำเร็จให้ใส่ `"status": "error"` หน้าเว็บจะแสดง "โหลดไม่สำเร็จ")
3. อัปเดต `config/project_registry.csv` / `project_finance_map.csv` เมื่อมีงานหรือเอกสารใหม่ (สคริปต์จะแจ้งงานที่ยังไม่ผูก Project ID)
4. `python3 scripts/import_projects.py` → ต้องไม่มีหัวข้อ "ต้องตรวจ" ค้าง (หรือยอมรับเป็นข้อจำกัดที่แสดงบนหน้า)
5. `python3 design/patch_pages.py` → `node scripts/build_pages.js` → `node scripts/build-static.js --key <กุญแจนอก repo> --out site` → `node scripts/site_test.js site <กุญแจ>`
6. ตรวจใน GitHub Desktop ว่ามีแต่ `site/` และโค้ด ไม่มี `design/`, `data/`, `raw/` แล้วเปิด PR

## ข้อจำกัดที่แสดงบนหน้า
- ทะเบียนทั้งหมดยังเป็นฉบับเสนอ → KPI "โครงการยืนยันแล้ว" = 0 จนกว่าจะยืนยัน (หน้าแสดงแถบแจ้ง)
- ไม่มีงบอนุมัติ ความคืบหน้าหน้างาน และชั่วโมงทำงาน → แสดง "ไม่มีในระบบ" / "ยังไม่มีค่าที่เจ้าของโครงการยืนยัน" / "ข้อมูลไม่พอ"
- การวางแผนสั่งซื้อ LPG และ TankConfig ยังอยู่ใน Power BI ตามขอบเขตเดิม หน้าโครงการไม่แตะส่วนนี้
